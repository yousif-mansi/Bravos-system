## What to build

Manage products and variants with cashier product-code lookup. Deliver the complete staff/customer behavior below with the necessary persistence, business rules, API, usable Arabic UI and verification. The approved parent specification is authoritative.

## Acceptance criteria

- [ ] Manager creates/edits products with unique product-level codes, editable categories/subcategories, sizes/colors, explicit variants, default selling prices and optional variant overrides. Price is identical across channels.
- [ ] Cashier searches by product code and selects a specific size/color. Duplicate codes and invalid combinations fail with useful UI/API errors; website visibility alone cannot forbid POS lookup or an otherwise permitted sale.
- [ ] The cashier receives only permitted selling information; manager-only catalog writes and private data are denied at the HTTP boundary. Empty/unstocked variants do not invent availability.
- [ ] Verify manager maintenance and cashier lookup through real PostgreSQL HTTP tests and a focused Arabic UI flow; retain later-ready image/publication fields without building the later storefront.
- [ ] Run the established typecheck, architecture, relevant behavior tests and build gates; preserve existing checks and record verification. No application test is considered passed merely because it is written.
