## Current focused evidence

The new root [storefront experience test](../../tests/browser/storefront-experience.spec.ts) and all four checkout browser cases passed together, **5/5**, in the isolated [combined log](../../.scratch/storefront-foundation/sf06-sf09-verification/sf12-accessibility-combined-final.log). The [workspace typecheck](../../.scratch/storefront-foundation/sf06-sf09-verification/sf12-accessibility-typecheck.log) and [storefront production build](../../.scratch/storefront-foundation/sf06-sf09-verification/sf12-accessibility-storefront-build.log) also passed. Sixteen [final screenshots](../../.scratch/storefront-foundation/sf06-sf09-verification/sf12-accessibility-evidence/) support the viewport/focus review. The main agent inspected checkout at 320px, not-found at 390px and CSS zoom wrapping. Local presentation changes make the checkout edit-cart and not-found return links at least 44px tall; scoped controls use a border that measured 3.71:1 against white. The isolated-only Windows teardown tweak was not copied into the root application.

The SSR catalog fault injection used pinned Node 22.13.1/pnpm 10.34.5, fresh test PostgreSQL and API, a faulting proxy and Playwright Chromium at 390×844. The [result JSON](../../.scratch/storefront-foundation/sf12-ssr-verification/source/.local/ssr-recovery-evidence/result.json) reports all browser assertions passing; [loading](../../.scratch/storefront-foundation/sf12-ssr-verification/source/.local/ssr-recovery-evidence/loading-390.png), [failed](../../.scratch/storefront-foundation/sf12-ssr-verification/source/.local/ssr-recovery-evidence/failed-390.png) and [recovered](../../.scratch/storefront-foundation/sf12-ssr-verification/source/.local/ssr-recovery-evidence/recovered-390.png) screenshots capture the states. The main agent inspected failed/recovered screenshots and accepted the visible error, recovery layout and retained cart count. The process exited 1 only during existing Windows testkit teardown when its closed-port probe received `EACCES` on `::1:55434`; all four test ports were subsequently confirmed closed. This is a passing browser-behavior observation with a harness teardown failure, not a clean command run. No production files changed in that probe.

No new backend, typography or asset choice is required for this quality pass. SF-12 may close only after the remaining integrated evidence, limitations and main-agent review are recorded against the final changes.
