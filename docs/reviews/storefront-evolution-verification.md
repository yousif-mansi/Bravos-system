The user confirmed web-embedding permission for the supplied font families after the local license inventory. The implementation copies minimal original font files without conversion; the confirmation is session authorization, not a claim that the demo font name establishes a general commercial license. The supplied inspiration image informed the direction; its artwork/layout was not copied into the storefront.

Numbered gallery selectors are intentional: they expose selected state and image count without downloading additional thumbnail images. This is a transfer-reduction design choice, not a measured SF-11 performance result. Selected full media still use the existing access-controlled media path without a persistent optimizer/cache workaround.

## Narrow behavioral repair

An accepted submission can now be replayed when public ordering is subsequently disabled. The checkout route calls `replayAcceptedSubmission` to read the existing operation and validate its request fingerprint; it does not create a new order while ordering is closed. A missing accepted operation retains the disabled response. This bounded recovery repair changes the API route/application read path only; no schema migration or public DTO change belongs to this evolution scope.

## Isolated demo

The [demo guide](../development/storefront-demo.md) documents a separate named PostgreSQL database, API, media directory and owner account. The runner uses real catalog/taxonomy/receiving/delivery/checkout APIs, four explicitly selected variant pairs per product and branch-specific stock. It seeds 16 fictional products, 15 public, with coming-soon/out-of-stock/hidden and whole-basket branch scenarios. Clearly marked vector illustrations are development artwork, not photographs of BRAVOS merchandise. A non-production frontend banner identifies the preview. No operational database or `.local/dev.env` replacement is part of the demo.
