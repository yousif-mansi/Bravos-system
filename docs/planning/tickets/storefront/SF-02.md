# SF-02 — Product wall tiles and image contract

**Phase:** 0. **Status:** Approved; awaiting dependencies and content gates. **Blocked by:** SF-01.  
**Outcome:** Current browse shows a consistent photographic wall with honest prices/availability and reliable media behavior.

## Scope and files

- Existing: `apps/storefront/app/page.tsx` (replace repeated card markup only).
- Proposed: `apps/storefront/app/components/product-card.tsx`, `shop-wall.tsx`, `product-media.tsx`, `shop-wall.module.css`.
- Tests: affected assertions in `tests/browser/storefront.spec.ts`, `tests/browser/catalog-media.spec.ts`.
- Reference only: `app/public-catalog.ts`, `next.config.ts`, public DTOs. No changes to fetch/caching/contracts.

## Acceptance criteria

- [ ] Tiles use the returned summary ID/name/preview/availability/lowest price; label starting prices as such and handle null without inventing zero.
- [ ] Near-zero-gutter, flat 4:5 imagery; four wide-screen columns and two phone columns where legible, with accessible narrow/zoom fallback.
- [ ] Out of Stock and Coming Soon stay visible/non-orderable as appropriate; Hidden never appears. Price remains visible without hover.
- [ ] Product links and concise captions work by keyboard/touch; missing/broken images have a stable, accessible fallback. No fabricated second-angle hover image.
- [ ] Reserve image space, prioritize only genuine above-fold lead media and lazy-load the remainder; preserve direct raw catalog URLs and no-store revocation. No optimizer or service-worker media cache.
- [ ] Existing cart and product navigation behavior and hooks remain intact.

## Verification and risks

Typecheck; storefront and catalog-media Playwright scenarios, including removal/Hidden revocation and 390px overflow. Check first/below-fold request behavior and image failures. Risk: optimizing through Next would bypass intended media revocation; CSS sizing alone does not shrink downloaded source files. No catalog uploads or source-data edits in this ticket.
