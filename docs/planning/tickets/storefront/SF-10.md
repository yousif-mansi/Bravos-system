## Acceptance criteria

- [x] Arabic form clearly separates required name/mobile/area/address from optional alternate phone/landmark/notes; correct labels and mobile input affordances preserve validation rules.
- [x] Existing native required-field validation gains visual feedback, `aria-invalid`, associated error IDs/guidance and focus. Track presentation state from native invalid events and clear it appropriately on correction; values remain after errors. No new validation policy or parallel custom validator.
- [x] Merchandise, discounts/coupon, configured delivery fee and final COD total are bound to existing authoritative quote values. No client recomputation or fee assumption.
- [x] Cart/area/coupon changes still invalidate a reviewed quote; stale in-flight responses cannot be accepted. Existing submission eligibility is unchanged.
- [x] Clear distinction between reviewing price, submitting, uncertain response, recovery, ordering closed, and successful pending request. Success provides reference and later WhatsApp confirmation, not a paid/stock-reserved claim.
- [x] Retry uses the persisted exact operation/request and preserves later cart additions. Never replace uncertain-submit recovery with a generic fresh POST retry.
- [x] Quiet shell, no campaign motion/upsell, no keyboard or sticky-summary obstruction. Loading says `لحظات...`; failures explain next safe action.
- [x] Missing configured delivery areas renders the existing unavailable path clearly, with no hard-coded fallback fee/area.
