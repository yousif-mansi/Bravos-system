## What to build

Configure delivery areas and submit validated guest COD requests. Deliver the complete staff/customer behavior below with the necessary persistence, business rules, API, usable Arabic UI and verification. The approved parent specification is authoritative.

## Acceptance criteria

- [ ] Manager edits supported Fayoum areas and fees without a release. Checkout displays selected configured charge and final order value, validates supported area, and requires name/primary mobile/detailed address.
- [ ] Alternate phone, landmark and notes are optional in actual API requests and UI. Customer can apply an eligible coupon and review offer/coupon/merchandise/charge totals.
- [ ] Submission rechecks current aggregated variant availability and publication status, records a pending guest COD request with stable identity and clear success result, and deducts/reserves nothing or consumes no coupon usage.
- [ ] An old cart requesting three when two remain fails usefully; repeated submission after lost response cannot create another request. Retain original requested values for later WhatsApp-agreed revisions.
- [ ] Verify area edits, fee calculations, optional omissions, duplicate/invalid quantity, pending no-hold and guest form behavior through HTTP plus a real storefront checkout flow.
- [ ] Run the established typecheck, architecture, relevant behavior tests and build gates; preserve existing checks and record verification. No application test is considered passed merely because it is written.

## Specification coverage

Stories: 55, 56, 57, 58, 59, 61, 64, 111, 114. Acceptance scenarios: A06, A10, A13, A29, A35. Scenarios shared with later tickets are extended there; only the behavior in this ticket is its completion contract.

55. As a customer, I want the submitted cart rechecked against current availability, so that an old cart cannot knowingly order three units when only two remain.
56. As a customer, I want checkout without creating an account and payment by cash on delivery, so that ordering follows BRAVOS's accepted process.
57. As a customer, I want checkout to request my name, primary mobile, delivery area and detailed address, so that staff can contact me and arrange delivery.
58. As a customer, I want alternate phone, landmark and notes to be optional, so that I can add helpful details without being forced to supply them.
59. As a customer, I want to see the configured fee for my Fayoum delivery area and the final order value, so that I understand the amount requested.
61. As a customer, I want a clear order-submission result, so that I know my request awaits staff confirmation.
64. As a cashier, I want pending online requests to hold no stock, so that unconfirmed requests do not block physical sales.
111. As a cashier or customer, I want to apply an eligible coupon to the current basket, so that its reduction is shown before cash-sale completion or order submission.
114. As the manager, I want to maintain supported Fayoum delivery areas and fees used by checkout validation and totals, so that the actual area list and charges remain editable operating data.
