## Acceptance criteria

- [ ] Existing text search and category filtering remain server-backed with current `q`/`category` URL semantics.
- [ ] Active filters are visible as individually removable chips with Clear all, including no-result states; controls have labels, focus and clear selected state.
- [ ] Sorting offers existing default order, Arabic name and starting-price ascending/descending, missing prices last. No newest/popularity/material/size/color facets without supporting data.
- [ ] Sort operates on the full returned matching summary set, not a misleading partial page. A UI-only `sort` query preserves search/category and browser back/forward; backend request parameters remain unchanged.
- [ ] Four-column desktop/two-column phone wall follows foundation, with visible price/caption and responsive control layout; filters stay discoverable rather than hidden behind unlabeled icons.
- [ ] Empty search explains next action; loading says `لحظات...`; failed reads show an error and safe retry instead of perpetual loading.
- [ ] No detail-fetch-per-card, pagination rewrite, extra data model or route added.
