# SF-00 — Content and visual asset readiness

**Phase:** 0. **Status:** Complete — requirements and inventory reviewed; production asset gaps explicitly remain. **Blocked by:** Final approved roadmap revision (completed).  
**Outcome:** A concrete visual-input specification and honest readiness inventory allow foundation work to proceed without fabricated production content.

## Scope and files

- Create `docs/planning/storefront-content-readiness.md`: verified existing assets, use/approval status, missing inputs, crop rules, copy requirements and ticket gates.
- Read-only inventory: official logo folders, `apps/storefront/public/brand/`, existing public catalog imagery and supplied project assets. Do not upload, rename, replace or modify catalog/business data.
- Optional local evaluation artifacts belong in ignored scratch storage and must be marked as evaluation-only; no fake products, campaigns or prices enter production source/data.

## Required specification

- Hero: one approved real brand/garment image, source/usage rights, desktop and mobile crop intent, focal point, short Arabic lead caption and one existing destination. Prefer 16:9 desktop and 4:5 mobile prepared crops; avoid destructive cropping. Provide source masters around 2400px wide desktop/1200px wide mobile when available; smaller sources must not be upscaled and called production-ready.
- Product: actual garment front, back/alternate angle, fabric/detail, and on-body fit where supplied. A truthful single image remains supported; no invented angles or variant mapping. Consistent 4:5 wall frame; gallery preserves garment detail and source order. Aim for 1600px-long-edge source detail, with optimized delivery sizing decided in SF-11.
- Image rules: reserve dimensions, no baked-in CTA/text, no misleading color/material retouch, approved crop/focal point, file/source/license record. Product media continues through current revocable API; static hero assets remain separate.
- Placeholders: neutral stable missing-image fallback only, no substitute fashion imagery claiming to show the product. Existing demo images are diagnostic, not approved launch content. No empty story modules or fake campaigns.
- Copy: exact product/catalog facts remain authoritative; approved hero/campaign text, alt descriptions and optional fit/fabric/care/style facts must record source and approval. No inferred claims, guarantees, scarcity or shipping times. COD/WhatsApp copy must match existing workflow.

## Acceptance criteria

- [x] Existing assets are inventoried with dimensions/type and candidate purpose; suitability and approval are distinct fields.
- [x] Hero/product/crop/placeholder/copy requirements above are documented with a missing-input checklist and affected tickets.
- [x] Required commerce content is separated from optional campaigns/editorial; absence of optional content renders nothing and never weakens access to the shop.
- [x] Official logos are reused, never recreated. Existing `cover.jpg` is evaluated, not automatically assumed to be an approved campaign hero.
- [x] SF-01 readiness specification can close even if production photography is pending; SF-03/SF-06/SF-08 visual-content gates stay explicit. No false claim of launch asset readiness.
- [x] Main agent reviews readiness decisions; no catalog data, uploads, business values or application code changed by SF-00.

## Verification and risks

Sol inventories files/dimensions and copy sources; main agent judges visual suitability and selects requirements. Review resulting manifest against files without modifying them. Largest risk is confusing existing test imagery or an available asset with approved product/campaign photography. Record unknown rights/approval rather than inventing either.
