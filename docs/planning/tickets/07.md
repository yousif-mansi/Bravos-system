## What to build

Record employee expenses and manager corrections with immediate totals. Deliver the complete staff/customer behavior below with the necessary persistence, business rules, API, usable Arabic UI and verification. The approved parent specification is authoritative.

## Acceptance criteria

- [ ] Manager and employee record an online expense with amount, date, category, description and active authorized branch; it affects totals immediately without approval.
- [ ] Employee lists/details show only own expenses in authorized branch context; manager can inspect both branches/all employees. Forged actor/branch inputs cannot bypass this.
- [ ] Manager corrects/cancels a saved expense with original record plus linked reason/actor/time, applying one effective change without hard deletion. A500-to 50 correction yields 50, not 550 or a duplicated adjustment.
- [ ] Provide usable Arabic entry/list/detail/correction workflows and HTTP tests for attribution, immediate totals, roles, duplicate corrections and original-history preservation.
- [ ] Run the established typecheck, architecture, relevant behavior tests and build gates; preserve existing checks and record verification. No application test is considered passed merely because it is written.

Stories: 7, 8, 89, 90, 91, 92. Acceptance scenarios: A01, A02, A27. Scenarios shared with later tickets are extended there; only the behavior in this ticket is its completion contract.

8. As the manager, I want to view every employee's sales and expenses, so that I can oversee both branches.

91. As the manager, I want saved expenses included in reports immediately, so that reporting does not depend on an approval queue.
