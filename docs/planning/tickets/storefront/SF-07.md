# SF-07 — Persistent product commerce

**Phase:** 3. **Status:** Approved; awaiting dependencies and content gates. **Blocked by:** SF-06.  
**Outcome:** Price, variant decisions and the add action stay reachable while the customer views the garment.

## Scope and files

- Existing: `app/products/[productId]/product-purchase-panel.tsx`, product `page.tsx` composition and proposed `product-page.module.css`.
- Proposed beside panel: `product-rail.tsx`, `sticky-commerce-bar.tsx`, `bag-feedback.tsx` as presentational views.
- Tests: `tests/browser/storefront.spec.ts`, `tests/browser/catalog-media.spec.ts`.
- `cart-provider.tsx` and DTOs remain read-only.

## Acceptance criteria

- [ ] Desktop commerce rail stays visible where viewport height permits; on constrained height it remains scrollable/reachable rather than clipping controls. Mobile bar respects safe area and page bottom spacing.
- [ ] Both presentations use the existing single selected-variant/quantity state and add callback. One interaction adds once; no duplicate forms, state owners or analytics emissions.
- [ ] Exact selected variant price is visible. Labeled size/color choices resolve existing IDs; unavailable combinations remain disabled, with textual states and no invented swatch colors.
- [ ] Existing initial selection, quantity caps, cart-aware remaining quantity and orderable gates remain unchanged. Coming Soon/Out of Stock do not gain an enabled action.
- [ ] Mobile bar shows price, selected size/color summary, an accessible path to change selection and the same add action. It never covers errors, focused controls or meaningful content.
- [ ] Successful add gives immediate, visible and announced non-blocking feedback with a cart link; count updates through existing cart state. Failure feedback is distinct and actionable.
- [ ] Existing size guide is reachable; do not fabricate material data or couple gallery changes to variants without API support.

## Verification and risks

Typecheck; existing quantity/variant/aggregated persistent-cart browser tests plus exact-price changes, one-click-one-add, disabled combinations, sticky overlap and keyboard checks. Risk: two visual purchase surfaces can accidentally duplicate state/actions. Keep state and all validation in the existing purchase-panel owner; review diff for behavior changes.
