## What to build

Browse the Arabic storefront and maintain a valid guest cart. Deliver the complete staff/customer behavior below with the necessary persistence, business rules, API, usable Arabic UI and verification. The approved parent specification is authoritative.

## Acceptance criteria

- [ ] Build the separate Next.js public storefront with photography-led neutral styling, Arabic RTL category browsing/search and rendered product pages with images, descriptions, optional guides and exact size/color choices.
- [ ] Guest cart persists useful selections, edits quantities within known per-variant availability and aggregates duplicate lines. Out-of-stock pages remain viewable with label and no order action; Coming Soon/Hidden follow publication rules.
- [ ] Configurable WhatsApp/social contacts have useful accessible links without automated messages or invented production contact values. Internal dashboard/POS/Returns navigation and bundles are absent.
- [ ] Verify real phone/desktop browsing/cart behavior, refresh persistence, availability changes and accessible Arabic forms. No customer accounts, advanced filters, wishlist/reviews, payments or tracking portal.
- [ ] Run the established typecheck, architecture, relevant behavior tests and build gates; preserve existing checks and record verification. No application test is considered passed merely because it is written.
