**Phase:** 4. **Status:** Implemented and verified locally; pending user review/commit. **Original dependency:** SF-02 (batch exception below).
**Outcome:** Customers can verify exactly what is in the cart, repair stock changes and proceed confidently.

## Scope and files

- Existing: `apps/storefront/app/cart/page.tsx` rendering only.
- Proposed: `app/cart/cart-line.tsx`, `cart-summary.tsx`, `cart.module.css`; reuse ProductMedia and action styles.

## Acceptance criteria

- [x] Name, selected size/color, quantity, current price and subtotal are clear; controls and remove action work by touch/keyboard.
- [x] Explain that adding to cart does not reserve stock and final delivery/discount totals are reviewed at checkout. No false final-total or shipping promises.
- [x] Existing changed-stock/price and unavailable-item actions remain visible; no silent removal or bypass of checkout eligibility.
- [x] Empty, hydrating, refresh-failed and storage-unavailable states have distinct useful copy; safe existing retry/actions remain available. Do not display failure as indefinite loading.
- [x] Persistent, aggregated, cross-tab and legacy-cart behavior remains exact; no storage migration or new cart model.
- [x] Mobile summary/action is reachable without overlaying line controls; no upsell wall or invented trust badges.

## Verification and risks

Typecheck; storefront browser cart suite including quantity aggregation, refresh, reload, cross-tab, corrupt/blocked storage, retained items; checkout smoke. Risk: page co-locates rendering and reconciliation. Extract display props/callbacks only; review all effects unchanged. Do not rewrite cart provider for visual convenience.
