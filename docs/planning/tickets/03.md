## What to build

Receive merchandise and inspect central stock with separate FIFO batches. Deliver the complete staff/customer behavior below with the necessary persistence, business rules, API, usable Arabic UI and verification. The approved parent specification is authoritative.

## Acceptance criteria

- [ ] Manager finalizes an online receipt with variant quantities, costs and receipt date; one atomic accepted operation persists receipt, distinct cost batches and stock movements. Identical retries return the original result; changed payload under the identity fails.
- [ ] Available stock is shared centrally, never branch-specific. Receipt of ten units costing 100 followed by ten costing 140 preserves both costs and quantities without an average or overwritten batch.
- [ ] Manager can inspect receipts, batch quantities/costs and low-stock variants; cashier reads expose aggregate availability and selling prices without cost data. Default low-stock threshold is three, configurable globally and per variant.
- [ ] Verify rollback, duplicate requests, role privacy and separate-batch receiving through real PostgreSQL HTTP operations and a receiving UI workflow; define the Inventory public transaction contract needed by cash sales.
- [ ] Run the established typecheck, architecture, relevant behavior tests and build gates; preserve existing checks and record verification. No application test is considered passed merely because it is written.

## Specification coverage

Stories: 21, 22, 23, 24, 29, 30. Acceptance scenarios: A03, A05, A12. Scenarios shared with later tickets are extended there; only the behavior in this ticket is its completion contract.

21. As the manager, I want both branches and online orders to consume one central variant balance, so that there are no independently maintained branch or website inventories.
22. As the manager, I want to receive variants with quantities, purchase costs and receipt dates online, so that new merchandise increases central stock with traceable costs.
23. As the manager, I want new-cost units to remain separate from old-cost units, so that receiving merchandise never averages or overwrites older costs.
24. As the manager, I want sales and confirmed orders to allocate from the oldest available purchase-cost batch first, so that costs follow the agreed FIFO method.
29. As the manager, I want a low-stock alert at three available units or fewer by default, so that I can identify variants needing attention.
30. As the manager, I want configurable global and per-variant low-stock thresholds, so that alert levels fit different products.
