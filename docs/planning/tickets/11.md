## What to build

Use cached promotions and reconcile offline coupon overuse. Deliver the complete staff/customer behavior below with the necessary persistence, business rules, API, usable Arabic UI and verification. The approved parent specification is authoritative.

## Acceptance criteria

- [ ] Already signed-in offline cashiers use cached prices and still-valid cached offers/coupons, respecting cached eligibility/date/local-usage information and employee deduction rules.
- [ ] Synchronizing a physically completed sale preserves accepted paid values even if a global coupon limit or rule changed while disconnected. Record coupon discrepancy for management without dropping the sale or silently repricing it.
- [ ] Manager can inspect the retained sale and usage discrepancy; reconciliation/deduplication cannot consume usage or deduct stock a second time.
- [ ] Prove outage at Cairo offer boundaries, global overuse after competing activity and retries through real browser storage/sync and HTTP operations. Restricted purchase costs remain absent from cached pricing data.
- [ ] Run the established typecheck, architecture, relevant behavior tests and build gates; preserve existing checks and record verification. No application test is considered passed merely because it is written.
