## What to build

Fulfill online orders and close inspected failed deliveries. Deliver the complete staff/customer behavior below with the necessary persistence, business rules, API, usable Arabic UI and verification. The approved parent specification is authoritative.

## Acceptance criteria

- [ ] Permitted representative/manager actions mark confirmed orders Shipped then Delivered without another stock deduction. Delivered alone becomes completed online reporting value.
- [ ] Cancel pending before shipment with zero restoration; cancel confirmed before shipment releases retained allocation and consumed coupon once. Do not permit routine cancellation to free goods still with a courier.
- [ ] Delivery failed remains unavailable until staff physically receive/inspect the parcel; manager-authorized final posting restores only sellable retained allocations once, preserving nonsellable/unreceived quantities.
- [ ] Manager terminal cancellation of the inspected undelivered failed order releases consumed coupon once. Failure/receipt alone does not release it. No courier receivable/remittance/settlement bookkeeping or auto-messaging.
- [ ] Verify transitions, invalid jumps, partial inspection, duplicate receipt/release and role permissions through HTTP plus order detail UI.
- [ ] Run the established typecheck, architecture, relevant behavior tests and build gates; preserve existing checks and record verification. No application test is considered passed merely because it is written.
