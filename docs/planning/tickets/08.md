## What to build

Manage automatic offers and select the greatest eligible saving. Deliver the complete staff/customer behavior below with the necessary persistence, business rules, API, usable Arabic UI and verification. The approved parent specification is authoritative.

## Acceptance criteria

- [ ] Manager creates/edits/activates scheduled percentage/fixed automatic offers scoped by eligible products/categories and controls combinations. Operating rules are editable data.
- [ ] Basket pricing selects the greatest-saving eligible automatic offer using Cairo date boundaries, then later coupon, then employee deduction. Default is one automatic offer and one eligible coupon; no unrequested employee discount restriction.
- [ ] Cashier sees an understandable offered price breakdown and retains accepted rule effects/unit paid values on completion. Later rule/catalog edits do not reprice completed sales.
- [ ] Verify eligibility, competing offers, date boundaries, equal/capped allocation and manager-only rule writes via real HTTP pricing/sale operations and a focused manager/cashier UI flow.
- [ ] Run the established typecheck, architecture, relevant behavior tests and build gates; preserve existing checks and record verification. No application test is considered passed merely because it is written.
