## What to build

Coordinate quantity corrections and reconcile late completed sales. Deliver the complete staff/customer behavior below with the necessary persistence, business rules, API, usable Arabic UI and verification. The approved parent specification is authoritative.

## Acceptance criteria

- [ ] Manager synchronizes known tills and briefly pauses stock-changing work before finalizing an available-quantity correction with previous/corrected values, reason, actor/time and count boundary/device acknowledgements.
- [ ] Exclude protected confirmed items from the available count; a disconnected device cannot be presumed paused. Keep late completed sales and discrepancies visible.
- [ ] If late movement is already included in the physical count, manager reconciliation must avoid a second deduction. Resolve actual missing receipt/count/movement before releasing more stock; positive correction requires actual batch/cost provenance.
- [ ] Verify controlled event ordering, retries, late arrivals, unknown-cost incompleteness and stale devices through HTTP/browser recovery; deliver a focused adjustment/reconciliation workflow without adding full stock-count sessions or damage ledgers.
- [ ] Run the established typecheck, architecture, relevant behavior tests and build gates; preserve existing checks and record verification. No application test is considered passed merely because it is written.
