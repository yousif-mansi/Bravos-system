## Acceptance criteria

- [ ] Manager decrypts/validates archive in staging and sees links/totals/differences before confirmation. Reconcile newer and queued work and pause writes; never silently replace newer activity.
- [ ] Keep pre-restore snapshot, preserve stable actor/business IDs and dedup records, revoke sessions and advance restore-generation marker on activation. Staff credential reprovision and separate owner recovery remain viable without exporting active secrets.
- [ ] Late old-generation device sales are retained for manager reconciliation instead of silently dropped or applied twice. Wrong password, corruption or invalid links fail without harming the valid database.
- [ ] Perform a real independent-database restore drill plus browser queued-sale recovery; prove coherent records/allocations/money, rollback/failure behavior and preview/confirmation authorization.
- [ ] Run the established typecheck, architecture, relevant behavior tests and build gates; preserve existing checks and record verification. No application test is considered passed merely because it is written.
