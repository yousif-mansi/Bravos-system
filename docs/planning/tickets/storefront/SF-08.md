# SF-08 — Factual product chapters

**Phase:** 3. **Status:** Partially implemented locally: supplied description and size guide use factual disclosures; focused local checks pass, approved fit/fabric/care/style content and rich demo review remain open. **Evidence:** [evolution delivery record](../../../reviews/storefront-evolution-verification.md). No missing chapter facts are invented.
**Outcome:** Interested customers can read fit, fabric, care and styling information after the garment, without invented claims or empty sections.

## Scope and files

- Existing: `app/products/[productId]/page.tsx`, optional existing size-guide rendering.
- Proposed: adjacent `product-chapters.tsx`, `product-chapters.module.css`; optional `apps/storefront/app/content/product-editorial.ts`.
- Tests: chapter-present/absent scenarios in `tests/browser/storefront.spec.ts`.

## Acceptance criteria

- [ ] Preserve existing description and size guide; render Fit → Fabric → Care → Style only for sections whose content exists and is approved.
- [ ] Existing free text is not parsed into inferred material/care facts. If supplied chapter copy needs a frontend content file, key it by existing product ID and record source/approval; no business values or new API fields.
- [ ] Product-specific content disappears with Hidden/missing product pages; orphaned entries never create public products or links.
- [ ] Short sections/accessible disclosure controls support Arabic reading; no empty accordions, padding-only chapters or lifestyle essay filler.
- [ ] Style is factual copy/approved imagery, not an inferred recommendation engine. Optional product links resolve only to existing public products; omit invalid ones.
- [ ] At least one approved representative product demonstrates the chapter treatment and another demonstrates omitted chapters; missing copy blocks content acceptance, not shopping functionality.

## Verification and risks

Typecheck; present/missing/orphan content cases, size guide, keyboard disclosure and RTL screenshots. Risk: API lacks structured chapters, so content drift is possible; keep the editorial map small and provenance explicit. Main agent approves copy presentation; integrate product composition serially with SF-07.

The local production build and final focused 7/7 browser rerun pass. Synthetic product captures establish local layout/loading behavior only; no approved representative product with all editorial chapters is recorded. Chapter-content acceptance therefore remains open.
