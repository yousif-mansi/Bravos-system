## Acceptance criteria

- [ ] Complete home → filter/sort → product/variant → cart → quote → pending-request journey with real test PostgreSQL; verify existing aggregate analytics are not duplicated by new UI surfaces.
- [ ] At 320/390/768/1024/1440px and 200% zoom: no unintended horizontal overflow, obscured fields, clipped Arabic or inaccessible sticky actions. Verify RTL with mixed Latin names/numbers and long text.
- [ ] Keyboard path covers skip link, navigation, filter chips, gallery, variants, cart and checkout; visible focus, logical order, selected/disabled states and no traps. Touch targets ≥44px; contrast meets 4.5:1 normal text and 3:1 large text/meaningful control boundaries.
- [ ] Slow/failed public requests, missing images, empty results, not-found, blocked storage, ordering closed and uncertain submission have distinct loading/error/recovery states. Retry cannot duplicate orders or silently lose cart lines.
- [ ] Reduced motion, screen-reader labels/status announcements and mobile keyboard/safe-area behavior reviewed. No private costs/profit data or internal links appear in public UI/responses/bundles.
- [ ] Preserve and pass existing Hidden/Coming Soon/Out of Stock, exact variant price, quantity, quote invalidation, lost-response and cross-tab regressions.
- [ ] Run typecheck, architecture checks, production build, affected storefront/catalog-media/checkout browser suites and public storefront/catalog/checkout HTTP suites. Record exact commands/results and any pre-existing unrelated failures.
- [ ] Physical iOS Safari/Android Chrome results are recorded or explicitly left as release blockers; emulation is not presented as hardware verification.
- [ ] Main agent reviews screenshots, diff and report. User receives changed files, evidence and remaining launch inputs before commit approval. No automatic deployment or next-phase work.
