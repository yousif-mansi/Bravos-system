## What to build

Correct receiving quantities and historical costs through linked records. Deliver the complete staff/customer behavior below with the necessary persistence, business rules, API, usable Arabic UI and verification. The approved parent specification is authoritative.

## Acceptance criteria

- [ ] Manager corrects saved receiving with reason/actor/time and original retained values, accounting for intervening consumed/returned quantities rather than overwriting history.
- [ ] An explicit cost 100-to 140 correction retains original 100 plus linked 40 and updates effective remaining/allocated cost. A new receipt 140 alone never reprices an older 100 batch/sale.
- [ ] A later sellable return of that corrected allocation restores/reverses effective 140, leaving no phantom 40 cost on a fully returned unit. Preserve original-batch identity and linked adjustment traceability.
- [ ] Test correction before/after allocation and return, retries, unavailable quantity reversal and permissions against real PostgreSQL; show original/effective receiving detail in the manager UI.
- [ ] Run the established typecheck, architecture, relevant behavior tests and build gates; preserve existing checks and record verification. No application test is considered passed merely because it is written.
